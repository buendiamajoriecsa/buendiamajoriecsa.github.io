Problem-Solving Portfolio & Cybersecurity Case

Case Study: Empty Field Submission Bug in Student Form

1. Problem

Users were able to submit student records even when important text fields (like Student Name or ID) were left completely blank, resulting in incomplete database entries.

2. Possible Causes

  • Missing input validation attributes in the HTML form elements.
  • Lack of conditional checking inside the JavaScript function before saving to localStorage.

3. Diagnostic Procedure

  • Tested the web form by clicking the "Add Student" button without typing anything.
  • Observed that empty rows or undefined values were successfully added to the student list table.

4. Solution

  • Added the required attribute to HTML input fields.
  • Implemented an if statement in JavaScript to check if fields are empty before executing the save function.

5. Lesson Learned

Client-side input validation is essential to prevent dirty data entry and maintain overall data quality in web applications.

STEP 18: Cybersecurity Case Study — SQL Injection (SQLi)

1. What is the vulnerability?

SQL Injection (SQLi) is a web security vulnerability that allows an attacker to interfere with the queries that an application makes to its database[cite: 5]. It occurs when untrusted user input is directly concatenated into a database query string without proper validation or sanitization[cite: 5].

2. How can it happen?

It happens when developers construct dynamic database SQL queries by directly combining user inputs (such as login fields, search bars, or URL parameters) into the SQL string[cite: 5].

3. What are the risks?

  • Unauthorized Access: Attackers can bypass authentication forms without valid credentials[cite: 5].
  • Data Exposure: Sensitive database records, user accounts, and passwords can be leaked[cite: 5].
  • Data Tampering: Unauthorized modification, deletion, or corruption of critical database data[cite: 5].

4. How can developers prevent it? (Code Comparison)

❌ Vulnerable Code Example (Direct Concatenation):

// Dangerous: Input is joined directly into the query
String query = "SELECT * FROM users WHERE username = '" + userInput + "' AND password = '" + passInput + "'";
// An attacker entering "' OR '1'='1" bypasses the check.

✅ Secure Code Example (Parameterized Query / Prepared Statement):

// Safe: Placeholders (?) separate user data from database logic
String query = "SELECT * FROM users WHERE username = ? AND password = ?";
PreparedStatement stmt = connection.prepareStatement(query);
stmt.setString(1, userInput);
stmt.setString(2, passInput);
ResultSet rs = stmt.executeQuery();

5. What security practices should be implemented?

  • Use Prepared Statements: Always utilize parameterized queries to treat user input as data, not executable code[cite: 5].
  • Input Validation & Sanitization: Enforce strict input types, lengths, and character filtering on client and server sides[cite: 5].
  • Principle of Least Privilege: Restrict database account permissions so the web application only accesses required resources[cite: 5].
